01 · Managing Security & Identity

入站與出站驗證

代理人同時面對兩個方向的信任問題:誰能存取代理人?代理人能代表使用者存取什麼?

Inbound Authentication

「誰是這個使用者?他被允許呼叫這個代理人嗎?」

User→App→Agent
  • ✓使用者驗證(如 Amazon Cognito)
  • ✓API 金鑰(系統對系統)
  • ✓聯合驗證(企業 SSO)
  • ✓IAM SigV4 或 JWT Bearer Token

Outbound Authentication

「這個代理人是它宣稱的身份嗎?能代表使用者存取此資源嗎?」

Agent→Tools, resources, gateways
  • ✓IAM 角色(AWS 服務)
  • ✓OAuth Client Credentials(機器對機器)
  • ✓OAuth Authorization Code(使用者委派存取)
01 · Managing Security & Identity

三種授權模式

Default

SigV4

AWS 預設驗證機制,透過 IAM 憑證驗證入站請求;Gateway 以 Service Role 進行出站驗證。

M2M

OAuth 2-Legged (2LO)

Client Credentials Grant,應用程式以自身身份存取資源,適合自動化系統對系統通訊。

Delegated

OAuth 3-Legged (3LO)

Authorization Code Grant,使用者明確同意後,代理人才能代表使用者存取資源。

02 · AgentCore Identity

AgentCore Identity 關鍵能力

傳統身份系統為人類設計;AgentCore Identity 則是為橫跨多系統自主運作的代理人打造的集中式身份中樞。

Workload Identity

穩定的數位錨點,跨部署環境與驗證方式維持一致的代理人身份。

安全權杖庫

集中保存第三方憑證與 OAuth Token,降低同意疲勞並自動處理更新。

憑證提供者

內建 Google、GitHub、Slack、Salesforce 等提供者,亦支援自訂 OAuth2。

細緻存取控制

Just-enough access、委派授權與身份感知的授權判斷。

保留既有身份系統

與 Okta、Microsoft Entra ID、Amazon Cognito 相容,免遷移使用者。

完整稽核軌跡

多層安全與完整日誌記錄,支援企業合規與追蹤需求。
