01 · Supported Frameworks

開源代理人框架比較

沒有單一「最佳」框架,依失敗容忍度、狀態複雜度與資料整合需求選擇合適的框架。

Model-centric

Strands Agents SDK

輕量型、具型別工具呼叫,強調安全性(權限、逾時、重試)。

  • 最少樣板程式碼
  • 內建多代理人模式
  • 正式環境級可觀測性
  • 可控性相對較低
  • 社群規模較新
Role-based

CrewAI

以角色為基礎的多代理人協作,支援任務拆解與 HITL。

  • 清楚的角色設定
  • 穩健的短 / 長期記憶
  • 文件完整、社群活躍
  • 偏主觀、難客製
  • 持久記憶仍在演進
Stateful graph

LangGraph / LangChain

以狀態圖建模流程(分支、迴圈、檢查點),適合多步驟工作流。

  • 可處理複雜狀態流程
  • 節點可自帶代理人
  • 成長中的社群
  • 版本間可能不穩定
  • 依賴 LangChain/Core
RAG-first

LlamaIndex

以資料與 RAG 為核心,提供索引、檢索器與路由器。

  • 進階 RAG 與索引能力
  • 可組合式查詢引擎
  • 內建評估與追蹤工具
  • 流程控制常需外部協調
  • 對索引/嵌入調校敏感
02 · AgentCore Runtime

Runtime 核心特色

傳統無伺服器服務為短暫任務設計;AgentCore Runtime 則為代理人的長時間、有狀態推理而生。

Session 隔離

每個 Session 擁有獨立的 microVM,提供持久且專屬的執行環境。

框架 / 模型 / 協定彈性

支援多種開源框架、任何模型(Bedrock、SageMaker、外部),及 MCP、A2A 協定。

多模態即時串流

雙向串流文字、圖片、音訊、影片,酬載上限達 100MB。

即時與長時任務並存

~200ms 快速初始化,同時支援長達 8 小時的非同步長任務。

內建驗證與身份

透過 AgentCore Identity 整合 IAM 與 OAuth 2.0 的入站驗證。

專屬可觀測性

內建追蹤代理人決策過程,協助除錯與效能優化。

02 · AgentCore Runtime

Runtime 三大核心概念

Runtime & Hosting

代理人程式碼執行的託管層,負責資源配置、監控與效能一致性。

Endpoints & Versions

可定址的存取點,對應特定代理人版本;預設 alias 自動指向最新版本。

Sessions

隔離的執行情境,使用專屬 microVM,最長可執行 8 小時。

Session 生命週期:

03 · Infrastructure and Deployment

部署方式:容器化 vs. 直接程式碼

Container-based Deployment

  • ✓使用 Docker + Amazon ECR 完整掌控執行環境
  • ✓映像檔可達 2GB,支援複雜相依套件
  • ✓支援多種語言與執行環境
Dockerfile → ECR → Runtime Endpoint

Direct Code Deployment

  • ✓免 Docker / ECR / CodeBuild,以 .zip 快速上傳
  • ✓限 Python 3.10–3.13
  • ✓壓縮 250MB / 解壓縮 750MB 上限
.zip → Runtime Endpoint

AgentCore Starter Toolkit 三步驟部署流程:

1agentcore configure 設定資源、IAM 角色與驗證
→
2agentcore launch 部署至 AgentCore Runtime
→
3agentcore invoke 帶入酬載呼叫代理人
