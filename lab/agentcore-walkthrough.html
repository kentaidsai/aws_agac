Task 1.1　基礎設置與基本智能體建立

FOUNDATION

目標是先組出一個「能跑」的客服智能體原型，再回頭看它缺了什麼——這個缺口正是 Task 1.2、1.3 要補的。

01 環境準備與函式庫載入 Cell 0–2

安裝依賴、匯入 AWS / AgentCore / Strands 函式庫，設定基本參數。

匯入 boto3、requests 等基礎套件；AgentCore 的 MemoryClient、StrategyType（先匯入供 Task 1.2 用）； Strands 的 Agent、BedrockModel、MCPClient 與 hook 相關類別。再從 lab_helpers.lab1_strands_agent 匯入四個本地工具與 SYSTEM_PROMPT、MODEL_ID。同時設定 REGION="us-east-1"、固定的 CUSTOMER_ID="customer_001" 與隨機的 SESSION_ID。這一步純粹是準備工作，尚未呼叫任何 AWS 服務。

02 檢視本地工具程式碼 Cell 3

動手之前，先理解智能體「能做什麼」——四個用 @tool 定義的本地工具。

純閱讀步驟，要求打開 lab_helpers/lab1_strands_agent.py 檢視：

工具用途
get_product_info()產品技術規格（寫死的模擬資料）
get_return_policy()退換貨政策（寫死的模擬資料）
get_technical_support()查 Bedrock Knowledge Base 做 RAG 檢索
web_search()用 ddgs 做 DuckDuckGo 網路搜尋

SYSTEM_PROMPT 定義了智能體的人設：一位電子產品電商的專業客服，並列出可用工具與使用原則。

03 建立 Basic Agent Cell 4–5

組裝第一個可運作的智能體——模型 + 系統提示 + 本地工具。

一個 Agent 的三個核心組成：Foundation Model（推理決策）、System Prompt（行為規範）、Specialized Tools（四個本地工具）。 收到問題後的內部流程：分析問題 → 選擇工具 → 執行工具 → 整合回應 → 品質檢查。 

model = BedrockModel(model_id=MODEL_ID, temperature=0.3, region_name=REGION)
basic_agent = Agent(
    model=model,
    tools=[get_product_info, get_return_policy,
           get_technical_support, web_search],
    system_prompt=SYSTEM_PROMPT
)

MODEL_ID 為 us.amazon.nova-pro-v1:0（Amazon Nova Pro），temperature=0.3 讓回答偏穩定。這一步完全在本機執行，沒有建立任何 AgentCore 雲端資源。

04 測試 Basic Agent Cell 6–7

驗證智能體能理解問題並正確呼叫工具產生答案。

呼叫 basic_agent("What's the return policy for laptops?")。智能體自主判斷應呼叫 get_return_policy(product_category="laptops")，取得政策內容後生成格式化的回覆。 驗證了「模型推理 + 工具呼叫 + 回應整合」這條最基本的 Agent 迴路已經跑通。

05 檢視原型限制 Cell 8

點出三個關鍵缺陷，作為進入 Task 1.2 / 1.3 的動機。

無持久記憶——只記得當下這次對話，換一個 session 就完全失憶； 僅本地工具——工具程式碼寫死在單一檔案，無法被其他智能體共用； 無身分管理——無法代表特定使用者行動，也沒有存取控制機制。 這三點分別對應 Task 1.2（Memory）與 Task 1.3（Gateway + Identity）要解決的問題。

Task 1.2　以 AgentCore Memory 強化記憶

MEMORY

情境：客戶三週前聯繫過客服，說明了偏好與歷史，這次卻得從頭重講一次——因為智能體只有單次對話的短期記憶。 這個任務要讓長期記憶的讀寫「自動發生」，不需要每次手動呼叫 Memory API。

06 建立／取得 AgentCore Memory 資源 Cell 9–10

建立具備兩種策略的 Memory 資源，作為智能體的長期記憶儲存層。

區分短期記憶（單次對話上下文，由 Strands Agent 框架自動處理）與長期記憶（跨對話萃取出的事實、偏好、摘要，由 AgentCore Memory 服務負責）。create_or_get_memory_resource() 先嘗試從 SSM 讀取既有的 memory_id， 不存在才建立新資源：

策略用途Namespace
USER_PREFERENCE擷取客戶偏好與行為support/customer/{actorId}/preferences
SEMANTIC儲存對話中的事實資訊support/customer/{actorId}/semantic

event_expiry_days=90：原始對話事件 90 天後過期，但萃取出的長期記憶不受影響。建立完成後 memory_id 寫回 SSM 供重複使用。

07 灌入歷史客服互動紀錄 Cell 11–12

模擬一位「老客戶」的歷史對話，讓 Memory 有素材可萃取洞察。

準備三段虛構歷史對話——MacBook Pro 過熱、遊戲耳機退貨政策、想找 16GB RAM 以上且偏好 ThinkPad 的程式設計筆電——組成 (text, role) 的 previous_interactions，透過 

memory_client.create_event(
    memory_id=memory_id, actor_id="customer_001",
    session_id="previous_session", messages=previous_interactions
)

寫入 Memory。寫入後 AgentCore Memory 會在背景非同步地依兩種策略，把原始對話萃取成結構化的長期記憶，這需要一些處理時間。

08 定義 Memory Hooks Cell 13–14

讓「讀取客戶情境」與「寫回新對話」自動發生，不需手動呼叫 Memory API。

CustomerSupportMemoryHooks(HookProvider) 掛上兩個回呼：retrieve_customer_context 掛在 MessageAddedEvent，回應前依兩個 namespace 各查詢最相關的 3 筆記憶，插入使用者訊息前方； save_support_interaction 掛在 AfterInvocationEvent，回應後把最新一組「提問／回覆」寫回 Memory。

整個機制對使用者完全透明——智能體程式碼幾乎不變，只多帶了 hooks=[memory_hooks]。

09 建立記憶增強智能體 Cell 15–16

把記憶 Hook 接上智能體，得到一個「有記憶」的客服智能體。

 
memory_hooks = CustomerSupportMemoryHooks(memory_id, memory_client, CUSTOMER_ID, SESSION_ID)
memory_agent = Agent(
    model=model,
    tools=[get_product_info, get_return_policy, get_technical_support, web_search],
    hooks=[memory_hooks],
    system_prompt=SYSTEM_PROMPT
)

與步驟 3 的 basic_agent 相比，工具與系統提示完全相同，唯一差異是多帶了 hooks=[memory_hooks]——記憶能力是「疊加」上去的，不需要重寫智能體本身的邏輯。

10 測試記憶增強智能體 Cell 17

驗證智能體能「想起」先前灌入的歷史偏好，不需客戶重新描述。

由於步驟 7 寫入的記憶需要背景非同步處理，先 time.sleep(90) 等待 90 秒，再呼叫 memory_agent("What are my laptop preferences?")。此時 retrieve_customer_context 會自動查到 「偏好 ThinkPad、需要 16GB RAM、重視 Linux 相容性」等先前萃取出的偏好並注入提問，客戶完全不需要重新說明需求。

Task 1.3　以 Gateway 與 Identity 擴展工具規模

GATEWAY / IDENTITY

企業往往有數百個 API、Lambda、工具，各自散落在不同智能體程式碼中，難以安全共用與治理。AgentCore Gateway 用統一的 MCP（Model Context Protocol） 端點暴露既有工具，AgentCore Identity 負責入站的 OAuth2 / JWT 驗證。

11 理解 Gateway 與 OAuth2/JWT 認證機制 Cell 18–19

動手之前，先弄懂 Gateway 的角色與它背後的安全機制。

AgentCore Gateway 是一個全託管的 MCP 伺服器：既有 Lambda、企業 API 可以被安全地暴露成工具，並支援語意化的工具探索。 AgentCore Identity 則扮演入站身分驗證（inbound auth，與 Cognito 協作）的角色；出站驗證（存取第三方服務）本 Lab 不使用。

12 準備 JWT 授權設定 Cell 20

從 SSM 取出 Cognito 設定，組成 Gateway 要求的授權設定物件。

 
auth_config = {
    "customJWTAuthorizer": {
        "allowedClients": [machine_client_id],
        "discoveryUrl": cognito_discovery_url
    }
}

allowedClients 是白名單，只有這個 client_id 簽發的 token 能通過驗證；discoveryUrl 讓 Gateway 動態取得 Cognito 的 OAuth metadata，不需手動填每個端點。

13 建立 AgentCore Gateway Cell 21–22

建立實際的 Gateway 資源，作為智能體與後端 Lambda 之間的安全代理層。

 
gateway_client.create_gateway(
    name="customersupport-gw",
    roleArn=get_ssm_parameter("…/gateway_iam_role"),
    protocolType="MCP",
    authorizerType="CUSTOM_JWT",
    authorizerConfiguration=auth_config,
)

建立後輪詢 get_gateway() 直到狀態變成 READY（FAILED 時拋出自訂例外），並把 gateway_id 寫回 SSM。程式碼也處理了 ConflictException（Gateway 已存在時直接讀取既有資源），讓這個 cell 可重複執行。 CloudFormation 只部署了一支 Lambda（CustomerSupportLambda）就能處理多個工具操作。

14 新增 Lambda Target Cell 23–24

告訴 Gateway 這支 Lambda 提供哪些工具、參數長什麼樣子。

以 JSON Schema 描述兩個工具，掛載到步驟 13 建立的 Gateway：

工具必填參數
check_warranty_statusserial_number（customer_email 選填）
web_searchkeywords（region／max_results 選填）

這與步驟 2 中本地 web_search() 功能相同，這裡改由 Gateway／Lambda 提供——示範同一種能力如何從「本地工具」遷移為「集中式工具」。 credentialProviderConfigurations 指定用 GATEWAY_IAM_ROLE，讓 Gateway 以自己的角色權限呼叫 Lambda。

15 建立具備 OAuth 認證的 MCP Client Cell 25–26

讓智能體能以合法的 JWT token 連上 Gateway，取得可呼叫的工具清單。

 
token_response = get_oauth_token()  # grant_type=client_credentials
access_token = token_response['access_token']

mcp_client = MCPClient(
    lambda: streamablehttp_client(
        gateway_url,
        headers={"Authorization": f"Bearer {access_token}"},
    )
)

get_oauth_token() 以 OAuth2 client-credentials 流程，帶著 client_id / client_secret / scope 向 Cognito 的 token 端點換取 JWT。Strands 的 MCPClient 包裝一個帶 Bearer token 標頭的 HTTP 串流連線——正是上面認證流程圖的程式碼實作。

16 合併本地與 Gateway 工具，建立 Enhanced Agent Cell 27–28

把記憶 Hook、本地工具、Gateway 工具合而為一，得到能力最完整的智能體。

 
mcp_client.start()
gateway_tools = mcp_client.list_tools_sync()

all_tools = [get_product_info, get_return_policy, get_technical_support] + gateway_tools
enhanced_agent = Agent(
    model=model, tools=all_tools, hooks=[memory_hooks], system_prompt=SYSTEM_PROMPT
)
